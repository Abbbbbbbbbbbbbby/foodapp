Which architecture fits best?

Three approaches for migrating the food line app to Cloudflare. All are mobile-first PWAs with offline support.

📱 PWA (Service Worker)
⬇ ⬆ offline queue (IndexedDB)
⚡ Cloudflare Workers (API)
🗄 Cloudflare D1 (SQLite)
Pages CDN → global edge delivery

A — Pages + Workers + D1 Recommended

A React PWA deployed to Cloudflare Pages. Service Worker caches the app shell and queues form submissions in IndexedDB when offline — syncs automatically when signal returns. Workers handle the API; D1 (SQLite at the edge) stores all family data. SMS OTP auth lives in a Worker.

Pros

  • Simplest stack, fewest moving parts
  • Offline-first built in via service worker
  • D1 is SQL — easy to migrate Bubble.io data
  • Pages CDN = fast load on any device
  • Low cost, scales to zero

Cons

  • D1 is still maturing (no row-level subscriptions)
  • Conflict resolution if two devices submit same family
📱 PWA (Service Worker)
⬇ ⬆ offline queue (IndexedDB)
⚡ Workers + 🔷 Durable Objects
🗄 D1 + ⚡ KV (session cache)
Stateful edge compute per session

B — Pages + Workers + Durable Objects + D1

Same PWA frontend, but uses Durable Objects to model each car check-in as a stateful edge session — strong consistency on concurrent updates, and the multi-family-per-car flow maps naturally. KV handles fast phone-number lookups.

Pros

  • Strong consistency per check-in session
  • Car-flow state machine is clean
  • KV = instant phone lookup

Cons

  • Significantly more complex to build and debug
  • Overkill — stations work independently
  • Higher cost at scale
📱 PWA (heavy client)
🗄 SQLite in-browser (wa-sqlite)
⚡ Workers (sync endpoint only)
🗄 D1 (authoritative store)
Full database lives on device

C — Local-First (wa-sqlite + Workers sync)

A true local-first app: the entire family database is replicated to each device using wa-sqlite (SQLite compiled to WebAssembly). The app works completely offline; a Worker syncs changes to D1 when connectivity returns. Zero latency for all reads and writes.

Pros

  • True zero-latency — no network for any operation
  • Works with zero signal indefinitely
  • Best possible UX for slow devices

Cons

  • Syncing thousands of family records to each device
  • Conflict resolution is hard to get right
  • Much higher build complexity
  • wa-sqlite is newer, less battle-tested

My recommendation is A — it directly fits your constraints (independent stations, mixed connectivity, full SQL migration), without the complexity of B or C. Click your preferred option, or let me know in the terminal.
