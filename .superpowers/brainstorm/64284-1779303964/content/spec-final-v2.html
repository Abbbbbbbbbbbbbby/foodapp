Food Line Check-In App — Final Design Spec

All changes applied including the unified lookup flow. Approve in the terminal to move to implementation planning.

Three Roles

Volunteer
Enter data only. Self-registers with name + phone. Role defaults to volunteer on registration.
Staff
Enter data + view records + data summary. Cannot manage accounts.
Admin
Full access. Manages accounts, sets roles, controls page access, exports data. 1–2 people.

Architecture — Cloudflare Pages + Workers + D1

Browser PWA → Service Worker (offline) + IndexedDB (queue)
             ↓ syncs when online
Cloudflare Workers → D1/SQLite · KV (sessions) · Twilio (SMS OTP)
Cloudflare Pages (CDN — global edge delivery)
  • Works offline — submissions queue locally, sync on reconnect, no data lost
  • D1 SQL maps directly to Bubble.io export — migration is a SQL import
  • Scales to zero between events · SMS OTP login, no passwords

Returning path detail
  1. Results screen: Ranked matches — name, partial phone, family size, last visit. "Not the right person → Register new" at bottom.
  2. Select families: Own family labeled "Their own family." Proxy families labeled "Also picking up for." None pre-checked — tap to select. Running count shown. Confirm disabled until ≥1.
  3. Log visit per family (loops): "No change" marks visit and advances. "Update info" opens mini-edit wizard. After last family → Done → Home.
